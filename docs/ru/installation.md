# Установка

Документ описывает установку с нуля до работающей системы. Порядок шагов важен:
каждый следующий опирается на предыдущий.

Все команды выполняются из папки, в которую распакован поставленный архив.

## Что должно быть готово заранее

- Сервер с Ubuntu и правами администратора.
- Файл лицензии от поставщика.
- Доступ к вашей CRM с правом читать звонки.
- Доступ в интернет - на время установки, чтобы скачать модели.

## Шаг 1. Подготовка сервера

Если сервер чистый, установите нужные программы. В архиве есть готовые скрипты:

```
scripts/platform/ubuntu/install_docker.sh
scripts/platform/ubuntu/install_postgres.sh
scripts/platform/ubuntu/install_deps.sh
```

Если планируете использовать видеокарту, дополнительно:

```
scripts/platform/ubuntu/install_nvidia_driver.sh
sudo reboot
scripts/platform/ubuntu/install_nvidia_docker_tools.sh
```

Перезагрузка после установки драйвера обязательна. Второй скрипт в конце сам
проверит, что видеокарта доступна из контейнера.

Если Docker и PostgreSQL уже стоят, достаточно `install_deps.sh`.

После него подготовьте рабочее окружение - без него команды управления системой
не запустятся:

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r scripts/requirements.txt
```

Эти же три строки печатает `install_deps.sh` в конце работы.

Обратите внимание: окружение нужно включать в каждом новом сеансе работы с
сервером - командой `source .venv/bin/activate` из папки с программой. Без этого
команды `deploy.py` сообщат, что не хватает нужных библиотек.

## Шаг 2. Выбор папок

Откройте файл `deploy.toml` и укажите, где размещать данные:

```toml
[paths]
data = "./runtime/data"
models = "./runtime/models"
secrets = "./runtime/secrets"
logs = "./runtime/logs"
configs = "./runtime/configs"

[network]
subnet = "172.28.0.0/16"
```

Пути могут указывать куда угодно на сервере. Записи разговоров (`data`) и модели
(`models`) занимают больше всего места - их обычно выносят на большой диск,
например `/mnt/storage/calls`.

Параметр `subnet` - это внутренняя сеть, в которой общаются программы. Менять
его нужно только если он совпадает с адресами вашей рабочей сети. Запомните это
значение, оно понадобится на шаге 5.

## Шаг 3. Первая команда

```
python deploy.py init
```

Команда создаст папки, скопирует в них примеры настроек и загрузит программы в
Docker. В конце она напечатает список того, что осталось сделать вручную, - с
уже подставленными вашими путями. Не закрывайте окно, эти подсказки пригодятся.

Команду можно выполнять повторно. Ваши настройки она не перезапишет: файлы,
которые уже есть, остаются нетронутыми.

## Шаг 4. Секреты

В папку `secrets` нужно положить несколько файлов - лицензию, строку подключения
к базе данных и ключ доступа к CRM. Каждый файл содержит одну строку.

Это описано в отдельном документе: [Секреты](secrets.md). Вернитесь сюда, когда
файлы будут на месте.

## Шаг 5. Доступ к базе данных

База данных установлена на сервере, а программы работают в контейнерах. Чтобы
они увидели базу, нужно три правки. Их точные значения печатает `deploy.py init`.

**Разрешите базе принимать подключения.** В файле `postgresql.conf`:

```
listen_addresses = '*'
```

**Разрешите подключения из внутренней сети.** В файле `pg_hba.conf` добавьте
строку, подставив `subnet` из вашего `deploy.toml`:

```
host all all 172.28.0.0/16 scram-sha-256
```

Оба файла лежат в `/etc/postgresql/<версия>/main`.

**Добавьте имя сервера.** В файле `/etc/hosts`:

```
127.0.0.1 host.docker.internal
```

После правок перезапустите PostgreSQL:

```
sudo systemctl restart postgresql
```

Саму базу данных создавать не нужно - система создаст ее при первом запуске.

## Шаг 6. Модели

Модели распознавания речи и анализа скачиваются отдельно - они большие. Команду
со всеми нужными параметрами печатает `deploy.py init`, выглядит она примерно
так:

```
python scripts/fetch_models.py deepdml/faster-whisper-large-v3-turbo-ct2 \
  unsloth/Qwen3-4B-Instruct-2507-GGUF:Qwen3-4B-Instruct-2507-Q4_K_M.gguf \
  -d ./runtime/models -t ./runtime/secrets/hf_token
```

Скачивание занимает время и требует нескольких гигабайт места.

Обратите внимание на последнюю часть команды - `-t ...hf_token`. Она указывает на
файл с ключом, который нужен только для моделей, требующих согласия с условиями.
Моделям из поставки он не нужен, и такого файла у вас, скорее всего, нет. Тогда
уберите эту часть команды целиком:

```
python scripts/fetch_models.py deepdml/faster-whisper-large-v3-turbo-ct2 \
  unsloth/Qwen3-4B-Instruct-2507-GGUF:Qwen3-4B-Instruct-2507-Q4_K_M.gguf \
  -d ./runtime/models
```

Если оставить ее, а файла нет, скачивание прервется с сообщением, что файл не
найден.

Если позже вы поменяете модель в настройках, скачать новую нужно будет вручную -
автоматически это не произойдет.

Некоторые модели требуют согласия с условиями использования. Что делать в этом
случае - в разделе [Решение проблем](troubleshooting.md).

## Шаг 7. Настройка под вашу компанию

К этому моменту система технически готова, но оценивать разговоры она будет по
примерам из поставки. Отредактируйте два файла в папке `configs/pipeline`:

- `criteria.toml` - критерии оценки менеджеров;
- `types.toml` - типы разговоров.

Это главная содержательная настройка. Подробно - в документе
[Критерии оценки](criteria.md).

Там же, в `configs/fetcher/config.toml`, укажите адрес вашего портала CRM:

```toml
[[source]]
name = "crm_main"
kind = "bitrix24"
portal_url = "https://ваш-портал.bitrix24.ru"
rest_url_file = "crm_main_rest_url"
```

## Шаг 8. Запуск

```
python deploy.py up
```

Команда проверит настройки, подготовит базу данных и запустит все три программы.
В конце она напечатает адрес веб-интерфейса.

## Шаг 9. Первый пользователь

Веб-интерфейс требует входа по логину и паролю, но пользователей пока нет.
Создайте первого:

```
python scripts/user.py add admin -d ./runtime/secrets/database_dsn
```

Пароль система спросит дважды, на экране он не отображается. Минимальная
длина - 8 символов.

Теперь откройте в браузере адрес, который напечатала команда `up`, и войдите.

## Что дальше

Первые разговоры появятся не сразу: загрузчик обращается к CRM раз в полминуты,
а обработка одного звонка занимает от нескольких секунд до нескольких минут.

За ходом работы удобно следить командой:

```
python deploy.py logs
```

Прервать просмотр - Ctrl+C, программы при этом продолжат работать.

Если что-то пошло не так, смотрите [Решение проблем](troubleshooting.md).

## Проверка результата

Система установлена правильно, если:

- `python deploy.py logs` не показывает повторяющихся ошибок;
- в веб-интерфейс удается войти;
- через несколько минут после запуска на странице "Звонки" появляются записи;
- у части звонков статус меняется на "Готово".
