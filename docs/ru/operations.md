# Эксплуатация

## Управление системой

Все повседневные действия выполняются одной командой - `deploy.py`. Это основная
и рекомендуемая точка управления: она проверяет настройки, подставляет пути из
`deploy.toml` и следит за тем, чтобы программы запускались согласованно.

Выполняйте команды из папки, в которую распакован архив.

| Команда | Что делает |
|---|---|
| `python deploy.py init` | Готовит сервер к первому запуску |
| `python deploy.py up` | Запускает систему |
| `python deploy.py stop` | Останавливает систему |
| `python deploy.py restart` | Перезапускает систему |
| `python deploy.py logs` | Показывает журнал работы |

Любую команду, кроме `init`, можно применить к одной программе:

```
python deploy.py restart pipeline
```

Названия программ: `fetcher` - загрузчик, `pipeline` - обработчик,
`webui` - веб-интерфейс.

Просмотр журнала прерывается сочетанием Ctrl+C. Программы при этом продолжают
работать.

## Когда что перезапускать

После изменения настроек программа должна прочитать их заново.

| Что изменили | Что перезапустить |
|---|---|
| Критерии, типы, настройки обработки | `restart pipeline` |
| Настройки CRM и загрузки | `restart fetcher` |
| Настройки веб-интерфейса | `restart webui` |
| Пути или сеть в `deploy.toml` | `stop`, затем `up` |

Команда `stop` не удаляет данные - записи разговоров и результаты анализа
остаются на месте.

## Полная остановка

Команда `stop` останавливает программы, но оставляет их зарегистрированными в
Docker. Если нужно убрать их полностью - например, перед переустановкой:

```
docker compose down
```

Выполнять из той же папки. Данные, настройки и база данных при этом не
затрагиваются - удаляются только сами контейнеры. Вернуть систему в работу можно
обычной командой `python deploy.py up`.

В остальных случаях пользуйтесь `deploy.py`: обращение к Docker напрямую обходит
проверки, которые она выполняет.

## Проверка состояния

Убедиться, что все работает:

```
docker compose ps
```

У всех трех программ должно быть состояние `running`. Если какая-то постоянно
перезапускается, смотрите ее журнал:

```
python deploy.py logs pipeline
```

## Пользователи

Доступ в веб-интерфейс дается по логину и паролю. Управление - командой
`user.py`. Во всех примерах путь к файлу подключения указан для настроек по
умолчанию.

Добавить пользователя:

```
python scripts/user.py add ivanov -d ./runtime/secrets/database_dsn
```

Пароль запрашивается дважды, на экране не отображается. Минимум 8 символов.

Сменить пароль:

```
python scripts/user.py passwd ivanov -d ./runtime/secrets/database_dsn
```

Посмотреть список:

```
python scripts/user.py list -d ./runtime/secrets/database_dsn
```

Удалить:

```
python scripts/user.py delete ivanov -d ./runtime/secrets/database_dsn
```

Если удалить последнего пользователя, войти в систему станет невозможно - об
этом команда предупредит. Восстановить доступ можно, создав пользователя заново.

Все пользователи равноправны, разделения на роли нет.

## Журналы работы

Журналы пишутся в папку `logs`, в отдельную папку на каждую программу. Файл
`latest.log` всегда указывает на текущий журнал.

Смотреть журнал удобнее командой `python deploy.py logs` - она показывает записи
всех программ сразу и в реальном времени.

Файлы журналов не разрастаются бесконечно: при достижении 10 МБ система
начинает новый файл и хранит пять последних.

Подробность записей настраивается параметром `level` в разделе `[logging]`
каждой программы. Обычное значение - `INFO`. Если нужно разобраться с проблемой,
временно поставьте `DEBUG` и перезапустите программу. Возвращайте `INFO` после
разбирательства: подробные журналы быстро занимают место.

## Место на диске

Система не удаляет старые записи разговоров автоматически. Со временем папка
`data` будет расти.

Посмотреть текущий объем:

```
du -sh ./runtime/data
```

Оценить рост просто: место занимают файлы записей, примерно 1 МБ на минуту
разговора. Сто звонков в день по пять минут - около 15 ГБ в год.

Если место заканчивается, удалите записи за старые периоды. Обработанные разговоры
лежат в папке `data/done`, разложенные по месяцам и дням - например,
`done/2026-03/14`. Поэтому удалять можно выборочно, целыми месяцами.

Результаты анализа при этом сохранятся: расшифровка, оценки и выводы хранятся в
базе данных. Пропадет только возможность прослушать запись - в карточке
разговора появится пометка, что запись недоступна.

## Резервное копирование

Копировать нужно две вещи.

**База данных** - там расшифровки, оценки и выводы. Это главное:

```
pg_dump -U calls call_analytics > backup.sql
```

**Папки `configs` и `secrets`** - настройки и доступы. Они небольшие, но их
потеря означает настройку системы заново.

Папку `data` копировать необязательно: записи разговоров обычно есть и в CRM.
Папку `models` копировать не нужно - модели скачиваются заново.

Разумный порядок: база данных - ежедневно, настройки - после каждого изменения.

## Очистка базы данных

Осторожно: команды ниже удаляют результаты работы.

Удалить все данные, сохранив структуру:

```
python scripts/db.py clear -d ./runtime/secrets/database_dsn
```

Удалить базу целиком:

```
python scripts/db.py drop -d ./runtime/secrets/database_dsn
```

Обе команды требуют подтверждения - нужно ввести пароль из строки подключения.
Это защита от случайного запуска.

После `clear` записи разговоров останутся на диске, но станут ненужными -
система о них больше не знает. Их можно удалить вручную.

## Срок действия лицензии

Работа системы ограничена сроком действия лицензии. Когда срок истекает,
программы останавливаются: новые звонки не загружаются и не обрабатываются, в
веб-интерфейс войти нельзя.

Данные при этом не пропадают. После установки нового файла лицензии и команды
`python deploy.py up` система продолжит работу и обработает накопившуюся
очередь.

Дату окончания видно в журнале при запуске любой программы. Обновлять лицензию
лучше заранее, не дожидаясь остановки.

## Обновление системы

1. Остановите систему: `python deploy.py stop`.
2. Сделайте резервную копию базы данных и папок `configs` и `secrets`.
3. Распакуйте новый архив в отдельную папку.
4. Перенесите в него `deploy.toml` из прежней установки.
5. Выполните `python deploy.py init`, затем `python deploy.py up`.

Ваши настройки при этом не перезаписываются. Если в новой версии появились
параметры, их примеры окажутся в папке `configs` рядом.

## Регулярные проверки

Раз в неделю имеет смысл посмотреть:

- работают ли все три программы - `docker compose ps`;
- нет ли повторяющихся ошибок в журнале;
- много ли звонков со статусом "Ошибка" в веб-интерфейсе;
- сколько осталось места на диске;
- не подходит ли к концу срок лицензии.
