# Секреты

Секреты - это пароли и ключи доступа. Они хранятся отдельно от остальных
настроек, в папке `secrets`, каждый в своем файле.

Правило одно: **файл содержит одну строку без кавычек и без лишних пробелов**.
Пустой файл считается ошибкой, программа с ним не запустится.

## Какие файлы нужны

| Файл | Для чего | Обязателен |
|---|---|---|
| `license.txt` | Лицензия на использование системы | Да |
| `database_dsn` | Подключение к базе данных | Да |
| `crm_main_rest_url` | Доступ к вашей CRM | Да |
| `hf_token` | Скачивание моделей | Иногда |

Имена файлов не жестко заданы - они указаны в настройках и при желании их можно
изменить. Приведенные выше имена используются по умолчанию.

## license.txt

Файл присылает поставщик. Положите его в папку `secrets` как есть, ничего не
меняя внутри: после правки файл перестанет действовать.

У лицензии есть срок действия. Что происходит по его истечении - в разделе
[Эксплуатация](operations.md).

## database_dsn

Строка подключения к базе данных. Формат:

```
postgresql://пользователь:пароль@host.docker.internal:5432/имя_базы
```

Пример:

```
postgresql://calls:kQ8vN2xR@host.docker.internal:5432/call_analytics
```

Разберем по частям:

- `calls` - пользователь PostgreSQL;
- `kQ8vN2xR` - его пароль;
- `host.docker.internal` - так программы обращаются к серверу, на котором стоит
  база. Оставьте это имя как есть, даже если база на том же компьютере;
- `5432` - порт PostgreSQL, стандартный;
- `call_analytics` - название базы. Придумайте любое, система создаст ее сама.

Пользователя базы данных нужно создать заранее, и у него должно быть право
создавать базы:

```
sudo -u postgres createuser --createdb --pwprompt calls
```

Пароль не должен содержать символы `@`, `:` и `/` - они разделяют части строки
подключения, и система разберет ее неправильно.

## crm_main_rest_url

Адрес для доступа к Bitrix24. Получить его можно так:

1. Войдите в Bitrix24 под администратором.
2. Откройте раздел "Приложения", далее "Разработчикам".
3. Выберите "Другое", затем "Входящий вебхук".
4. Отметьте права на телефонию, пользователей и CRM.
5. Сохраните и скопируйте появившийся адрес.

Адрес выглядит примерно так:

```
https://ваш-портал.bitrix24.ru/rest/1/abc123def456/
```

Этот адрес дает доступ к данным вашего портала. Обращайтесь с ним как с паролем.

Имя файла связано с названием источника в настройках загрузчика. Если вы
переименуете источник или добавите второй портал, файлов будет несколько - у
каждого свое имя, указанное в параметре `rest_url_file`.

## hf_token

Нужен, только если выбранная модель требует согласия с условиями использования.
Модели из поставки по умолчанию такого согласия не требуют, и файл не нужен.

Если при скачивании моделей система сообщит, что доступ закрыт, порядок действий
описан в разделе [Решение проблем](troubleshooting.md).

Этот файл используется только во время скачивания моделей. В работе системы он
не участвует.

## Как создать файлы

На Linux:

```
cd ./runtime/secrets
nano database_dsn
```

Впишите строку, сохраните - Ctrl+O, затем Ctrl+X.

Проверить, что файл в порядке:

```
cat database_dsn
```

Должна вывестись ровно одна строка.

## Безопасность

- Ограничьте доступ к папке: `chmod 700 ./runtime/secrets`.
- Не копируйте эти файлы в общие папки и не пересылайте в мессенджерах.
- Не добавляйте их в системы контроля версий.
- Программы читают секреты только на чтение и никогда их не изменяют.
- В журналах работы содержимое секретов не появляется.
