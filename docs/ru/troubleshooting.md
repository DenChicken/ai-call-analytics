# Решение проблем

## С чего начинать

Почти на любой вопрос отвечает журнал работы:

```
python deploy.py logs
```

Ищите строки со словами `ERROR` или `error`. Сообщения об ошибках написаны
понятным языком и обычно прямо указывают на причину.

Посмотреть, какие программы запущены:

```
docker compose ps
```

Программа, которая постоянно перезапускается, - первый признак неполадки.
Смотрите ее журнал отдельно, например:

```
python deploy.py logs pipeline
```

## Команды не запускаются

### Не хватает библиотек

```
ModuleNotFoundError: No module named 'psycopg'
```

Не включено рабочее окружение. Выполните из папки с программой:

```
source .venv/bin/activate
```

Это нужно делать в каждом новом сеансе работы с сервером. Если окружение вообще
не создавалось, вернитесь к первому шагу раздела [Установка](installation.md).

### Docker не найден

```
docker not found, install it and try again
```

Docker не установлен либо у пользователя нет прав на работу с ним. Проверьте:

```
docker ps
```

Если команда сообщает об отказе в доступе, добавьте пользователя в группу
docker и войдите в систему заново.

## Система не запускается

### Сообщение об ошибке в настройках

Программа пишет, какой параметр неверен и в каком файле. Например:

```
config error: missing required key 'port' in [server]
```

Откройте указанный файл и проверьте это место. Частые причины: пропущенная
кавычка, лишняя запятая, удаленная по недосмотру строка.

Сравните файл с примером из папки `examples` в поставке.

### Файл секрета не найден или пуст

```
secret file not found: /secrets/database_dsn
```

Проверьте, что файл есть в папке `secrets`, и что в нем ровно одна непустая
строка. Имя файла должно совпадать с указанным в настройках.

### Порт занят

```
'port' in [server] is 3000, but that port is already in use
```

На этом порту работает другая программа. Либо остановите ее, либо укажите другой
порт в `configs/webui/config.toml`.

### Проблема с лицензией

Сообщения о лицензии выглядят так:

```
license error: license file not found
license error: license expired on ...
```

В первом случае проверьте, что файл лицензии лежит в папке `secrets` и его имя
совпадает с указанным в настройках.

Во втором - срок действия истек, обратитесь к поставщику. Контакт указан в самом
сообщении. Данные при этом не пропадают: после установки новой лицензии система
продолжит работу и разберет накопившуюся очередь.

Обратите внимание: пока лицензия недействительна, программы будут пытаться
запуститься и останавливаться снова. Это ожидаемое поведение, а не поломка.

## База данных недоступна

```
database error: the database is unreachable
```

Проверьте по порядку.

**Работает ли PostgreSQL:**

```
sudo systemctl status postgresql
```

**Верна ли строка подключения.** Откройте файл `database_dsn` в папке секретов.
Убедитесь, что имя пользователя, пароль и название базы указаны правильно, а
адрес записан как `host.docker.internal`.

**Разрешены ли подключения.** В файле `postgresql.conf` должно быть
`listen_addresses = '*'`, а в `pg_hba.conf` - строка с вашей подсетью из
`deploy.toml`. После правок PostgreSQL нужно перезапустить.

**Есть ли запись в hosts.** В файле `/etc/hosts` должна быть строка
`127.0.0.1 host.docker.internal`.

Подробно эти настройки описаны в разделе [Установка](installation.md).

Отдельно проверить доступ можно так:

```
psql "postgresql://пользователь:пароль@localhost:5432/имя_базы" -c "SELECT 1"
```

Если и эта команда не работает, дело в самой базе, а не в системе.

## Звонки не загружаются

Проверьте журнал загрузчика:

```
python deploy.py logs fetcher
```

**Ошибка доступа к CRM.** Ключ доступа неверен или у него не хватает прав.
Создайте новый вебхук, убедившись, что отмечены права на телефонию,
пользователей и CRM.

**Звонки есть в CRM, но не появляются.** Скорее всего, они отсеиваются по
условиям отбора. Посмотрите в журнале строку вида "skipped ... records" - там
указано, сколько записей пропущено и почему: без записи разговора, слишком
короткие или слишком длинные.

Проверьте параметры `min_call_duration_seconds` и `max_call_duration_seconds` в
настройках загрузчика.

**Разговоры без записи не обрабатываются.** Это не ошибка: если в CRM запись
разговора не сохранилась, анализировать нечего.

**При первом запуске загрузилось мало звонков.** Проверьте
`initial_lookback_days` - по умолчанию система берет звонки только за последние
сутки.

## Звонки загружаются, но не обрабатываются

Посмотрите на дашборде показатель "В очереди".

**Очередь растет.** Обработчик не успевает. Это разбирается в разделе
[Производительность](performance.md).

**Очередь стоит на месте, ничего не обрабатывается.** Проверьте, работает ли
обработчик, и посмотрите его журнал.

**Обработчик перезапускается.** Обычно это нехватка памяти. Включите выгрузку
моделей или уменьшите нагрузку на видеокарту - см.
[Производительность](performance.md).

## Звонки со статусом "Ошибка"

Причина видна при наведении на статус в списке звонков. Что означает каждая:

| Сообщение | Причина | Что делать |
|---|---|---|
| Файл записи не найден | Запись удалена с диска | Обычно последствие ручной очистки |
| Расшифровка не дала результата | В записи нет речи | Тишина или обрыв связи, это нормально |
| Расшифровка пуста | Распознать речь не удалось | Проверьте качество записи |
| Разговор не помещается в контекст модели | Разговор слишком длинный | Увеличьте `context_tokens` или ограничьте длительность |
| Модель не уложилась в лимит ответа | Ответ оказался длиннее допустимого | Увеличьте `max_tokens` |
| Модель вернула некорректный ответ | Сбой анализа | Единичные случаи нормальны |
| Не заданы активные критерии | Файл критериев пуст | Проверьте `criteria.toml` |
| Не заданы активные типы звонков | Файл типов пуст | Проверьте `types.toml` |

Единичные ошибки - обычное дело, особенно на плохих записях. Тревожиться стоит,
если ошибками помечена заметная часть разговоров.

Система пытается обработать разговор несколько раз, прежде чем пометить ошибкой.

## Не удается скачать модели

**Требуется согласие с условиями.** Некоторые модели доступны только после
принятия условий их авторами. Проверить доступ можно так:

```
python scripts/fetch_models.py <название модели> -d ./runtime/models --check
```

Команда напечатает адреса страниц, на которых нужно принять условия. После этого
понадобится файл `hf_token` в папке секретов - см. [Секреты](secrets.md).

**Скачивание прерывается.** Обычно из-за неустойчивого соединения. Запустите
команду повторно: уже скачанное не загружается заново.

**Не хватает места.** Модели занимают несколько гигабайт. Проверьте свободное
место командой `df -h`.

## Видеокарта не используется

Проверьте, что в `configs/pipeline/config.toml` действительно указано
`device = "cuda"` и `gpu_layers` отличается от `none`. Система определяет режим
именно по этим параметрам.

Проверьте, что видеокарта видна системе:

```
nvidia-smi
```

Если команда не работает, не установлен драйвер. Если работает, но система все
равно считает на процессоре, - не установлены средства работы с видеокартой из
контейнеров. Оба скрипта есть в поставке, см. [Установка](installation.md).

После установки драйвера сервер нужно перезагрузить.

## Не удается войти в веб-интерфейс

**Страница не открывается.** Проверьте, что программа работает
(`docker compose ps`), и что порт открыт в межсетевом экране:

```
sudo ufw allow 3000/tcp
```

**Логин или пароль не подходят.** Посмотрите список пользователей:

```
python scripts/user.py list -d ./runtime/secrets/database_dsn
```

Если нужного нет, создайте. Если есть - смените пароль командой `passwd`. Обе
команды описаны в разделе [Эксплуатация](operations.md).

**Пользователей нет вообще.** Такое бывает после очистки базы данных. Создайте
пользователя заново.

## Интерфейс работает, но данных нет

**Пустой дашборд.** Проверьте выбранный период - возможно, за него просто нет
звонков. Попробуйте "30 дней".

Проверьте фильтр по типам: если сняты все отметки, показывать нечего.

**Звонки есть, а оценок нет.** Значит, они еще не обработаны. Посмотрите их
статус в списке звонков.

**Не воспроизводится запись.** Файл удален с диска. Расшифровка и оценки при
этом сохраняются - недоступна только запись.

## Изменил настройки, ничего не поменялось

Настройки читаются при запуске. Перезапустите нужную программу:

```
python deploy.py restart pipeline
```

Какие изменения какую программу затрагивают - в разделе
[Эксплуатация](operations.md).

Учтите, что изменение критериев действует только на новые разговоры. Уже
оцененные не пересчитываются - подробнее в документе
[Критерии оценки](criteria.md).

## Если ничего не помогло

Соберите сведения перед обращением к поставщику:

1. Что именно происходит и с какого момента.
2. Вывод команды `docker compose ps`.
3. Журнал с ошибками. Чтобы получить подробный, временно поставьте
   `level = "DEBUG"` в настройках нужной программы, перезапустите ее и повторите
   действие, приводящее к проблеме.

Журналы лежат в папке `logs`, отдельно по каждой программе. Файл `latest.log`
всегда указывает на текущий.

Перед отправкой журналов просмотрите их: в них могут попасть сведения о клиентах
и содержание разговоров.
