# Настройки

Справочник по всем параметрам. Для повседневной работы он не нужен - большинство
значений менять не приходится.

## Где что лежит

Настройки разделены на два уровня.

**Файл `deploy.toml`** лежит рядом с `deploy.py`. В нем указано, где на сервере
размещать данные. Это единственный файл, где пути ведут к папкам сервера.

**Файлы `config.toml`** - по одному на каждую программу, в папках
`configs/fetcher`, `configs/pipeline` и `configs/webui`. В них пути выглядят как
`/data`, `/models`, `/secrets`, `/logs`, `/configs` - это внутренние обозначения,
и **менять их не нужно**. Система сама связывает их с вашими папками из
`deploy.toml`.

Имена файлов внутри настроек указываются без пути - только имя. Например,
`dsn_file = "database_dsn"` означает файл `database_dsn` в папке секретов.

После изменения настроек программу нужно перезапустить - см.
[Эксплуатация](operations.md).

## Правила записи

Файлы имеют формат TOML. Несколько правил:

- Строки в кавычках: `device = "cpu"`.
- Числа без кавычек: `port = 3000`.
- Да и нет пишутся как `true` и `false`, без кавычек.
- Строки, начинающиеся с `#`, - это пояснения, система их не читает.
- Разделы обозначены квадратными скобками: `[database]`.

Ошибка в файле не пройдет незамеченной: программа не запустится и напишет, где
именно проблема.

## deploy.toml

```toml
[paths]
data = "./runtime/data"
models = "./runtime/models"
secrets = "./runtime/secrets"
logs = "./runtime/logs"
configs = "./runtime/configs"

[network]
subnet = "172.28.0.0/16"
```

| Параметр | Назначение |
|---|---|
| `data` | Записи разговоров. Растет со временем |
| `models` | Модели. Несколько гигабайт |
| `secrets` | Пароли и ключи доступа |
| `logs` | Журналы работы |
| `configs` | Файлы настроек |
| `subnet` | Внутренняя сеть программ |

Пути можно указывать как относительно папки с программой (`./runtime/data`), так
и полностью (`/mnt/storage/calls`).

Параметр `subnet` меняют только при совпадении с адресами рабочей сети. Это же
значение должно быть разрешено в настройках PostgreSQL.

## Загрузчик

Файл `configs/fetcher/config.toml`.

### Что и откуда загружать

```toml
[[source]]
name = "crm_main"
kind = "bitrix24"
portal_url = "https://ваш-портал.bitrix24.ru"
rest_url_file = "crm_main_rest_url"
```

| Параметр | Назначение |
|---|---|
| `name` | Название источника, произвольное |
| `kind` | Тип CRM. Поддерживается `bitrix24` |
| `portal_url` | Адрес вашего портала |
| `rest_url_file` | Имя файла с ключом доступа в папке секретов |

Если порталов несколько, блок `[[source]]` можно повторить - с другим `name` и
своим файлом доступа.

### Отбор звонков

```toml
[fetch]
interval_seconds = 30
min_call_duration_seconds = 30
max_call_duration_seconds = 3600
initial_lookback_days = 1
max_records_per_cycle = 100
download_cooldown_seconds = 0
record_delay_minutes = 120
```

| Параметр | Назначение |
|---|---|
| `interval_seconds` | Как часто спрашивать CRM о новых звонках |
| `min_call_duration_seconds` | Короче этого - пропустить |
| `max_call_duration_seconds` | Длиннее этого - пропустить |
| `initial_lookback_days` | За сколько дней забрать звонки при первом запуске |
| `max_records_per_cycle` | Сколько звонков брать за один раз |
| `download_cooldown_seconds` | Пауза между скачиваниями |
| `record_delay_minutes` | Сколько выждать после разговора, прежде чем забирать запись |

Стоит настроить три параметра.

`min_call_duration_seconds` отсеивает бессмысленные звонки: тридцати секунд не
хватит на разговор, и оценивать там нечего. Если у вас много коротких, но
содержательных звонков, значение можно уменьшить.

`initial_lookback_days` действует только при самом первом запуске. Поставьте
больше, если нужно сразу набрать историю для статистики. Учтите, что все эти
звонки встанут в очередь на обработку.

`record_delay_minutes` защищает от неполных записей. Телефония сообщает о
звонке сразу после разговора, но сам файл записи готовится не мгновенно: если
забрать его слишком рано, вместо разговора можно получить короткий обрывок.
Система ждет указанное время и только потом забирает запись.

Из-за этого звонок появляется в интерфейсе не сразу, а спустя заданное время
после разговора. На дневную и недельную статистику это не влияет. Уменьшать
значение без необходимости не стоит: слишком малая задержка возвращает
неполные записи, и такие разговоры получают пустую расшифровку и нулевые
оценки. Значение должно быть меньше, чем `initial_lookback_days`, иначе при
первом запуске не найдется ни одного звонка.

### Обращения к CRM

```toml
[network]
connect_timeout = 5
read_timeout = 20
download_timeout = 120
max_retries = 5
backoff_base_seconds = 1
backoff_max_seconds = 30
requests_per_second = 2
```

Эти параметры определяют, сколько ждать ответа от CRM и сколько раз повторять
попытку при сбое. Менять их обычно не нужно.

`requests_per_second` ограничивает частоту обращений, чтобы не создавать нагрузку
на портал. Уменьшите, если CRM жалуется на слишком частые запросы.

## Обработчик

Файл `configs/pipeline/config.toml`. Здесь больше всего настроек, но
содержательных среди них немного.

### Очередь

```toml
[worker]
poll_interval_seconds = 15
max_attempts = 3
```

| Параметр | Назначение |
|---|---|
| `poll_interval_seconds` | Как часто проверять очередь, когда она пуста |
| `max_attempts` | Сколько раз пытаться обработать разговор до отметки об ошибке |

### Критерии и типы

```toml
[criteria]
file = "criteria.toml"

[types]
file = "types.toml"
```

Указывают имена файлов. Их содержимое разобрано в документе
[Критерии оценки](criteria.md).

### Распознавание речи

```toml
[asr]
repo_id = "deepdml/faster-whisper-large-v3-turbo-ct2"
local_dir = "faster-whisper-large-v3-turbo-ct2"
device = "cpu"
compute_type = "int8"
unload_after = false
```

| Параметр | Назначение |
|---|---|
| `repo_id` | Какую модель скачивать |
| `local_dir` | Папка модели внутри `models` |
| `device` | `cpu` или `cuda` (видеокарта) |
| `compute_type` | Точность вычислений |
| `unload_after` | Выгружать модель из памяти после работы |

Главный параметр здесь - `device`. Подробнее в разделе
[Производительность](performance.md).

```toml
[asr.transcript]
language = "ru"
beam_size = 5
condition_on_previous_text = true
hallucination_silence_threshold = 2.0
word_timestamps = true
vad_filter = true
min_silence_duration_ms = 300
speech_pad_ms = 400
```

Настройки качества распознавания. Значимый из них один - `language`, язык
разговоров. Остальные подобраны и менять их не рекомендуется.

### Анализ

```toml
[llm]
repo_id = "unsloth/Qwen3-4B-Instruct-2507-GGUF"
model_file = "Qwen3-4B-Instruct-2507-Q4_K_M.gguf"
gpu_layers = "none"
context_tokens = 8192
batch_tokens = 256
threads = 8
flash_attention = true
kv_cache_type = "int8"
offload_kv_cache = true
unload_after = false
```

| Параметр | Назначение |
|---|---|
| `repo_id`, `model_file` | Какую модель использовать |
| `gpu_layers` | Сколько работы отдать видеокарте: `none`, `all` или число |
| `context_tokens` | Насколько длинный разговор помещается в анализ |
| `threads` | Сколько ядер процессора использовать |
| `unload_after` | Выгружать модель из памяти после работы |

Остальные параметры относятся к экономии памяти и разобраны в разделе
[Производительность](performance.md).

Если разговоры не помещаются в анализ, система сообщит об этом ошибкой
"Разговор не помещается в контекст модели". Тогда нужно увеличить
`context_tokens` - но это потребует больше памяти.

```toml
[llm.sampling]
temperature = 0
top_p = 0.8
top_k = 20
min_p = 0.0
repeat_penalty = 1.05
seed = 0
```

Определяют, насколько предсказуемы ответы модели. `temperature = 0` означает,
что на одинаковых данных результат будет одинаковым - для оценки работы
сотрудников это правильное поведение. Менять не рекомендуется.

```toml
[llm.output]
list_items = 3
max_tokens = 1024
```

| Параметр | Назначение |
|---|---|
| `list_items` | Сколько пунктов в списках сильных сторон, слабых и рекомендаций |
| `max_tokens` | Ограничение длины ответа |

`list_items` можно менять по вкусу: три пункта - разумно, пять - подробнее, но
дольше.

### Инструкция для модели

```toml
[prompt]
label = "v3"
system_file = "prompts/system.txt"
user_file = "prompts/user.txt"
```

Пометка версии и имена файлов с инструкцией. Разобрано в документе
[Критерии оценки](criteria.md).

Пояснения к каждой части результата - что именно система должна написать в итоге
разговора, в сильных сторонах, в слабых и в рекомендациях - находятся в файле
`prompts/system.txt`, в разделе "ФОРМАТ ВЫВОДА". Именно эти строки задают стиль
выводов.

Менять их имеет смысл, если выводы получаются не такими, как вам нужно.
Например, если рекомендации выходят слишком общими, можно прямо потребовать
конкретики.

## Веб-интерфейс

Файл `configs/webui/config.toml`.

```toml
[server]
port = 3000
backend_path = ""

[display]
refresh_seconds = 5
page_size = 25
queue_size = 10
```

| Параметр | Назначение |
|---|---|
| `port` | Порт, на котором открывается интерфейс |
| `backend_path` | Оставьте пустым |
| `refresh_seconds` | Как часто страницы обновляют данные |
| `page_size` | Строк на странице списка звонков |
| `queue_size` | Строк в таблице очереди на дашборде |

Параметр `port` меняют при конфликте с другой программой. После изменения не
забудьте открыть новый порт в межсетевом экране.

Параметр `backend_path` нужен только при особой схеме публикации через сервер
доступа. В обычной установке он остается пустым.

Уменьшать `refresh_seconds` без надобности не стоит - частые обновления нагружают
базу данных.

## Журналы

Раздел `[logging]` есть у всех трех программ и устроен одинаково:

```toml
[logging]
level = "INFO"
external_logs = false
external_level = "WARNING"
```

| Параметр | Назначение |
|---|---|
| `level` | Подробность записей |
| `external_logs` | Записывать ли сообщения вспомогательных библиотек |
| `external_level` | Подробность таких сообщений |

Значения `level` от кратких к подробным: `CRITICAL`, `ERROR`, `WARNING`, `INFO`,
`DEBUG`, `TRACE`.

Обычное значение - `INFO`. При разборе неполадок временно ставят `DEBUG`.
`TRACE` пишет очень много и нужен редко.

## Настройки, которые не следует менять

В файлах есть разделы `[paths]`, `[database]`, `[storage]` и `[license]`. Они
описывают, где программы ищут файлы внутри себя. Значения в них уже верные, и
правка приведет к тому, что система не запустится.

Единственное, что там осмысленно менять, - имена файлов секретов, если вы решили
назвать их иначе.
